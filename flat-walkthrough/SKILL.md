# Floor plan → Mac + Android walkthrough

This pipeline shipped the "Type G 2BHK" walkthrough (Kozhikode, Landmark Builders): a Blender model built
from two plan images, Unreal Engine 5.8 Mac app with Lumen, Android APK with Cycles-baked lighting, a
furniture-free variant and a geo-referenced balcony view. Everything is generated by scripts. Nothing is
modelled by hand in a GUI. The scripts live in `kit/` and are copied into each new project by
`scripts/scaffold.py`. The worked example's docs are in `example_typeG/`. Read them when you need to know
what "done" looked like.

## Stage skills (read the one for the step you're on)

| Step | Skill | Output |
|---|---|---|
| Plan reading, dimensions, Blender shell, plan overlay check | `flat-plan-to-blender` | `blender/flat_<slug>.blend`, `docs/01_plan_analysis_and_design.md` |
| Builder style, furniture, materials, variant definitions | `flat-furnishing` | `furnish.py`, `unreal/scripts/variants.json` |
| Surroundings from lat/lon (terrain, houses, towers, trees) | `flat-environment` | `blender/environment.blend`, `/Game/Flat/Environment` |
| Unreal import, level, walk checks, Mac app per variant | `flat-unreal-mac` | `build/Mac*/…app` + zips |
| Baked lighting, mobile level, APK per variant, phone test | `flat-android` | `build/Android/*.apk` |

## Workflow

1. **Intake first** (`references/intake.md`). Read every plan image yourself, then ask in **one**
   `AskUserQuestion` round only for what you can't read or infer. Typical gaps: which unit is theirs on a
   floor plate, the floor number, the compass or facing direction, the builder name, style references, the
   variants and targets they want, and lat/lon if they want the environment. Record answers and every
   assumption in `project.json`. Don't block on things with a sensible default. Use the default, tag it [E],
   and list it in the checkpoint.
2. **Scaffold** the project. Use the folder the user chose, never a temp dir for real work:
   `python3 ~/.claude/skills/flat-walkthrough/scripts/scaffold.py <dest> --name Flat<Short> --title "<Title>" --plan <img> …`
   This copies the kit with identifiers renamed, the UE First Person content, the Poly Haven library
   (APFS clones), a new Android keystore and `FLAT_SPECIFIC.md` (the per-flat files you must rewrite).
3. **Checkpoint 1: shell + plan overlay** (`flat-plan-to-blender`). Show the overlay and the first renders,
   and get confirmation before furnishing. Wall errors found later cost every downstream stage.
4. **Checkpoint 2: furnished renders** (`flat-furnishing`). Show a review page of Cycles renders per room and
   iterate on style here. A re-render takes minutes; every Unreal or Android rebuild takes 15–30 min.
5. **Environment** (`flat-environment`), only if asked. Research first and confirm the findings with the user,
   then build.
6. **Mac** (`flat-unreal-mac`): furnished level → verification sweeps → environment → variant levels → package
   one app per variant.
7. **Android** (`flat-android`): per variant, bake → mobile level → APK → test on the user's phone over adb if connected.
8. **Docs**: one numbered markdown per stage in `docs/`, plus a README with a deliverables table, how to play,
   and rebuild commands. Say what was verified and what was not.

## Ground rules learned the hard way

- **Order matters.** `ue_build.py`'s level stage rebuilds `L_<Name>` from the interior export, which wipes
  the environment. Re-run `ue_environment.py`, then `ue_variant.py` for each variant, and only then the mobile
  copy. Variants copied from the furnished level before the environment existed don't get the view; this happened.
- **Never save test geometry into a shipping level.** A one-cube Lightmass test left a 10 m engine Plane at
  floor height. It showed as black jagged patches on Android bedroom floors. The kit strips
  `/Engine/BasicShapes` Plane/Cube in the variant and mobile copy steps.
- **Lightmass doesn't run on Apple Silicon** (UE 5.8 installed build). Android lighting is baked in Blender
  Cycles (`flat-android`).
- **GUI-only editor operations** (Save As, lightmap UV settings, viewport shots) run through the
  `Content/Python/init_unreal.py` hook:
  `FLAT_RUN=<abs script> FLAT_QUIT=1 UnrealEditor <uproject>`. Commandlet mode
  (`UnrealEditor-Cmd -run=pythonscript`) is for asset import only.
- **Long runs go in the background** (bake about 15 min, Mac cook about 10–20 min, Android cook about 13 min cold).
  Never poll in a loop; wait for the completion notice.
- **Verify before claiming.** Use screenshots from the packaged app or phone (adb `screencap`), not just the editor.
  If only config was checked, say so.
- **Variants are separate apps** with their own bundle id / Android package (`<package>.<variant>`), so all of them
  can be installed side by side.
- **Privacy.** Lat/lon is the user's home. Fetching imagery, elevation and OSM sends it to Esri, OpenTopoData and
  Overpass, so say so and get an OK first. Never print the keystore password.
- **Licences.** Poly Haven assets are CC0. Satellite imagery is for locating things only and never ships.
  Builder renders are visual references only and never ship.

## Tooling assumed (check on first use, tell the user what's missing)

Blender 4.x/5.x at `/Applications/Blender.app`. UE 5.8 at `/Users/Shared/Epic Games/UE_5.8` with the Android
platform. Android Studio (SDK at `~/Library/Android/sdk`, NDK 28, JBR keytool). Python 3 with numpy, scipy,
Pillow and scikit-image (the system python3 here has no numpy: use a venv, e.g.
`python3 -m venv ~/.venvs/flat && ~/.venvs/flat/bin/pip install numpy scipy pillow scikit-image`, after asking). adb is under `~/Library/Android/sdk/platform-tools` (not on PATH).
Disk: about 6 GB per project plus about 1 GB per app build.

## Files here

- `scripts/scaffold.py`: new project from the kit. `scripts/geo_fetch.py`: imagery, DEM and OSM around a pin.
- `kit/`: every pipeline script (reference implementation; Type G data inside the per-flat files).
- `base/`: UE First Person content and the Poly Haven texture/asset library (copied by scaffold).
- `example_typeG/`: the five docs from the Type G project (plan analysis, testing, Android, unfurnished, environment).
- `references/intake.md`: the intake checklist and question wording.
